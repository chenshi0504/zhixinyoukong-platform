# 学生自研算法能力设计

## 目标

平台中的学生自研算法能力采用“标准数据包 + 标准提交格式 + 统一评测器”的轻量方案。学生不必直接调用本地仿真平台、SUMO、CARLA 或 DTALite 环境，也能围绕同一题目的原始数据开发算法，并与平台基准算法结果进行可重复对比。

本次已将范围从单一“交通流短时预测”扩展为后端统一学生自研算法题库。统一入口为：

```bash
python backend/algorithms/student_algorithm_suite.py build
```

输出目录：

`backend/algorithms/student_packs`

教师可通过统一评测命令评测学生提交：

```bash
python backend/algorithms/student_algorithm_suite.py evaluate <task_id> <学生提交文件>
```

当前纳入统一题库的后端任务包括：

| task_id | 后端模块 | 学生提交内容 | 评测方式 |
|---------|----------|--------------|----------|
| `traffic_prediction` | 交通流预测 | 测试集流量预测 CSV | MAE、RMSE、MAPE、R2 |
| `data_fusion` | 多源数据融合 | 每帧每类别融合概率 CSV | 与平台贝叶斯融合基准的 MAE/RMSE |
| `signal_optimization` | 交通信号优化 | 周期和各相位绿灯时长 CSV | 与 Webster 基准的周期/绿灯误差和约束可行性 |
| `path_guidance` | 路径诱导 | OD 对路径序列和成本 CSV | 路径合法性、相对最短路成本 |
| `traffic_reconstruction` | 交通流重构 | 路段分时重构流量 CSV | 与观测流量的 MAE、RMSE、MAPE、R2 |
| `vehicle_speed_control` | 车速控制 | 控制实验汇总指标 CSV | 与 PID 基准的延误、速度等指标对比 |
| `coordination_control` | 三层级/多层级/分层控制 | 时序平均速度和等待车辆数 CSV | 与全协调基准时序指标的 RMSE |

暂不作为离线可复现题包直接评测的模块：

| 模块 | 原因 | 处理方式 |
|------|------|----------|
| `data_collection` | 依赖视频源、YOLO/ByteTrack 权重和推理环境 | 在文档中规定检测结果 JSON/轨迹 CSV 提交格式，后续有标注集后接入检测指标 |
| `carla_simulation` | 依赖 CARLA 服务、地图和传感器环境 | 规定轨迹、碰撞次数、完成率等指标提交格式 |
| `vehicle_dev_control` | 依赖车规级车辆控制或 CARLA 环境 | 并入 CARLA/车辆控制类指标规范 |
| `simulation` | 承载仿真环境，不是独立算法题目 | 由信号、路径、速度、协调任务复用 |

## 统一学生算法数据包

生成全部题包：

```bash
python backend/algorithms/student_algorithm_suite.py build
```

列出支持的任务：

```bash
python backend/algorithms/student_algorithm_suite.py list
```

每个题包目录都包含：

| 文件 | 用途 |
|------|------|
| `metadata.json` | 任务 ID、模块 ID、输入文件、提交列、主指标 |
| `student_submission_template.csv` | 学生提交格式模板 |
| `baseline_*` | 平台基准结果或基准指标 |
| 任务输入文件 | 学生可见的训练/测试/场景/路网/观测数据 |

统一包根目录还包含 `suite_metadata.json`，用于教师端或云端平台读取全部题目信息。

## 交通流预测数据包

生成命令：

```bash
python backend/algorithms/traffic_prediction/student_algorithm_pack.py
```

输出目录：

`backend/algorithms/traffic_prediction/student_pack`

统一套件也会把同一内容生成到：

`backend/algorithms/student_packs/traffic_prediction`

数据包文件：

| 文件 | 用途 |
|------|------|
| `raw_traffic_flow.csv` | 题目涉及的原始数据整理版 |
| `train.csv` | 学生训练数据，包含特征和 `target_total_flow` |
| `test_features.csv` | 学生预测用测试特征，不包含答案 |
| `student_submission_template.csv` | 学生提交格式模板 |
| `baseline_predictions.csv` | 平台基准算法在同一测试集上的预测结果 |
| `test_ground_truth.csv` | 教师评测用标准答案 |
| `metadata.json` | 特征、划分方式、评价指标和基准指标 |
| `README.md` | 面向学生的简要说明 |

数据包生成时得到的统一基准结果：

| 指标 | 数值 |
|------|------|
| MAE | 79.6619 |
| RMSE | 118.4984 |
| MAPE | 10.7515% |
| R2 | 0.937576 |

该结果与 `predictor.py` 的结果略有差异，是因为学生数据包在完整监督样本上先切分再建模，而原平台脚本先切分原始序列再分别构造滞后样本。后续统一对比以 `student_pack/metadata.json` 内的基准为准。

## 学生提交格式

学生提交 CSV 文件，至少包含两列：

```csv
sample_id,prediction_total_flow
2300,925.0
2301,918.0
```

约束：

- `sample_id` 必须与 `test_features.csv` 完全一致。
- `prediction_total_flow` 必须为数值。
- 不允许缺失样本、重复样本或额外样本。
- 学生可使用任意语言和任意算法，只要最终输出符合 CSV 格式。

## 统一评测

单模块交通预测评测命令：

```bash
python backend/algorithms/traffic_prediction/evaluate_student_submission.py <学生提交CSV>
```

统一套件评测命令：

```bash
python backend/algorithms/student_algorithm_suite.py evaluate traffic_prediction <学生提交CSV>
python backend/algorithms/student_algorithm_suite.py evaluate data_fusion <学生提交CSV>
python backend/algorithms/student_algorithm_suite.py evaluate signal_optimization <学生提交CSV>
python backend/algorithms/student_algorithm_suite.py evaluate path_guidance <学生提交CSV>
python backend/algorithms/student_algorithm_suite.py evaluate traffic_reconstruction <学生提交CSV>
python backend/algorithms/student_algorithm_suite.py evaluate vehicle_speed_control <学生提交CSV>
python backend/algorithms/student_algorithm_suite.py evaluate coordination_control <学生提交CSV>
```

示例：用基准预测文件自评。

```bash
python backend/algorithms/traffic_prediction/evaluate_student_submission.py backend/algorithms/traffic_prediction/student_pack/baseline_predictions.csv --output backend/algorithms/traffic_prediction/student_pack/baseline_evaluation.json
```

评测输出包括：

- 学生算法 MAE、RMSE、MAPE、R2。
- 平台基准算法 MAE、RMSE、MAPE、R2。
- 学生算法相对基准的 RMSE 差值和改进百分比。
- 是否在 RMSE 指标上超过基准。

当前主指标：RMSE，越小越好。

## 教学使用流程

教师准备阶段：

1. 运行基准算法，确认平台基准可复现。
2. 运行 `student_algorithm_pack.py` 生成数据包。
3. 将 `student_pack` 中除 `test_ground_truth.csv` 外的文件发给学生。
4. 在任务要求中说明提交 CSV 格式和主评价指标。

学生开发阶段：

1. 读取 `train.csv` 训练自研算法。
2. 读取 `test_features.csv` 生成预测。
3. 按 `student_submission_template.csv` 格式提交结果。
4. 报告中说明算法思路、特征处理、参数设置和与基准的预期差异。

教师评测阶段：

1. 收集学生提交 CSV。
2. 使用 `evaluate_student_submission.py` 批量评测。
3. 按 RMSE、MAE、MAPE、R2 生成排行和分析。
4. 结合报告说明给出成绩，不只看单一指标。

## 后端提交链路

平台原有“算法模板/学生算法脚本”API 继续保留，用于学生在平台内提交 Python 脚本、运行测试、教师查看结果。已通过以下后端测试验证：

```bash
python -m pytest backend/tests/test_algorithm_integration.py backend/tests/test_algorithm_properties.py -q
```

本次统一题包解决的是算法数据、基准结果和评测标准的整理问题；API 提交链路解决的是学生代码提交、执行日志和教师查看问题。两者可以组合使用：教师发布题包，学生提交 CSV/JSON 结果或脚本，平台统一保存与评测。

## 可扩展设计

其他模块可按同一接口扩展：

| 模块 | 数据包输入 | 学生输出 | 评价指标 |
|------|------------|----------|----------|
| 交通流重构 | 路段观测流量、OD 先验 | OD 矩阵或路段流量 | RMSE、MAPE、守恒误差 |
| 信号优化 | 固定路口流量与相位约束 | 配时方案 CSV/JSON | 平均延误、排队长度、通行量 |
| 路径诱导 | 路网边表、OD 对、边权 | 路径序列 | 路径成本、合法性、耗时 |
| 车速控制 | 参考速度、前车轨迹 | 控制序列或速度序列 | 跟踪误差、舒适性、安全约束 |
| 数据融合 | 多源观测和真值 | 融合目标状态 | RMSE、漏检率、误检率 |

建议所有题目统一包含：

- `raw_*`：题目原始数据。
- `train.*`：学生可见训练数据。
- `test_features.*`：学生可见测试输入。
- `*_ground_truth.*`：教师评测答案。
- `baseline_predictions.*` 或 `baseline_solution.*`：平台基准结果。
- `student_submission_template.*`：提交模板。
- `metadata.json`：字段、指标、基准和版本说明。
- `evaluate_*.py`：统一评测器。
