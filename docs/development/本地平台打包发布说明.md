# 本地平台项目打包与发布说明

本文说明如何将一个本地开发的平台项目打包为可交付安装包，并发布到另一台电脑或另一套运行平台。适用对象包括：前端页面、后端服务、算法模块、数据库/样例数据、第三方仿真软件、启动脚本和运行环境。

## 一、目标

打包的目标不是简单压缩源码，而是形成一个可运行、可验证、可维护的交付物。

交付物应满足：

- 解压或安装后能通过一个入口启动平台。
- 不依赖开发机固定路径，例如 `D:\xxx\project\output`。
- 前端、后端、算法、数据、外部软件路径都使用相对路径或配置文件。
- 敏感配置、开发缓存、日志、临时上传文件不进入发布包。
- 首次启动能自动检查运行条件，缺少环境时给出明确提示或自动配置。
- 交付包包含版本号、清单、启动说明和验证步骤。

## 二、推荐技术栈

### 1. 前端

- 技术：HTML、CSS、JavaScript，或 Vue/React/Vite 等前端框架。
- 发布形态：静态文件。
- 交付内容：`index.html`、页面目录、CSS、JS、图片、字体等资源。
- 注意点：前端 API 地址应使用相对路径或运行时配置，避免写死开发机地址。

### 2. 后端

- 技术：Python + FastAPI + Uvicorn。
- 数据访问：SQLAlchemy。
- 配置管理：`.env`、`config.local.env`、环境变量。
- 发布入口：统一启动脚本，例如 `start.bat` 或 `启动平台.bat`。
- 注意点：后端静态文件挂载、数据库路径、上传目录、算法输出目录都应基于项目根目录动态计算。

### 3. 数据与存储

- 本地数据库：SQLite，适合教学、演示、离线运行场景。
- 业务数据：放入 `backend/data/`、`data/` 或独立数据目录。
- 运行时数据：日志、上传文件、算法输出、缓存建议放到 `runtime/`、`.runtime/` 或用户数据目录。
- 注意点：样例数据和运行时数据分开，避免把开发过程产生的脏数据打进发布包。

### 4. 算法与仿真

- 科学计算：NumPy、Pandas、SciPy、Scikit-learn。
- 可视化与文档：Matplotlib、OpenPyXL、python-docx。
- 深度学习：PyTorch、GPyTorch、BoTorch 等。
- 交通仿真：SUMO、TraCI、sumolib。
- 外部程序：DTALite、NEXTA、CARLA 等。
- 注意点：算法模块不要写死外部软件路径，优先使用 `SUMO_HOME`、`APP_ROOT`、相对路径或配置项。

### 5. 打包与安装

可选方案：

- 便携压缩包：直接压缩发布目录，适合内测、教学机、实验室拷贝。
- 安装包：使用 Inno Setup、NSIS、WiX Toolset 等生成 `.exe` 安装器。
- 单文件桌面程序：使用 PyInstaller 打包 Python 桌面入口，再随附资源目录。
- 容器化：使用 Docker Compose 发布到服务器或云平台，适合服务端部署。

Windows 本地演示平台推荐：

- 第一阶段：便携压缩包。
- 第二阶段：Inno Setup 安装包。
- 第三阶段：带签名、版本更新、离线依赖包的正式安装器。

## 三、发布目录设计

建议先构建一个干净的发布目录，再压缩或制作安装包。

示例：

```text
release/
└─ 平台名称_本地_vX.Y.Z/
   ├─ backend/
   │  ├─ app/
   │  ├─ algorithms/
   │  ├─ data/
   │  ├─ requirements.txt
   │  └─ run.py
   ├─ frontend/
   │  ├─ index.html
   │  ├─ src/
   │  └─ assets/
   ├─ data/
   │  └─ README.md
   ├─ tools/
   │  └─ sumo/
   ├─ software/
   │  └─ README.md
   ├─ license/
   ├─ installer/
   │  └─ env/
   ├─ config.local.env
   ├─ bootstrap_start.py
   ├─ 启动平台.bat
   ├─ PACKAGE_MANIFEST.md
   └─ README.md
```

目录职责：

- `backend/`：后端服务、API、算法代码、数据库初始化逻辑。
- `frontend/`：前端静态页面和资源。
- `data/`：样例数据、内置数据说明。
- `tools/`：可随包发布的工具，例如 SUMO。
- `software/`：外部软件说明或轻量可执行文件。
- `installer/`：环境配置脚本、依赖清单、安装器脚本。
- `.runtime/`：首次启动后生成，存放虚拟环境、日志、缓存，不应预先打进发布包。

## 四、打包流程

### 1. 盘点运行边界

先列清楚平台运行需要哪些内容：

- 前端页面是否需要构建。
- 后端是否依赖数据库文件。
- 算法是否依赖模型、权重、CSV、XML、Excel、配置文件。
- 是否依赖 SUMO、DTALite、CARLA、VC++ Runtime、DirectX 等外部软件。
- 是否需要联网，例如调用云端 API、AI 模型 API、pip 下载依赖。
- 目标机器是否允许安装 Python、创建虚拟环境、访问互联网。

### 2. 清理开发内容

发布包不应包含：

- `.git/`
- `.vscode/`
- `.pytest_cache/`
- `__pycache__/`
- 日志目录
- 上传临时目录
- 开发机 `.env`
- 本地密钥、Token、API Key
- 旧版 `output/`、`dist/` 中无关构建产物
- 大量测试输出和中间结果

建议保留：

- `.env.example`
- `config.local.env`
- `requirements.txt`
- `PACKAGE_MANIFEST.md`
- 用户启动说明

### 3. 固化配置

配置文件应遵守两点：

- 不写开发机绝对路径。
- 不写密钥。

示例：

```env
LOCAL_APP_PORT=8000
CLOUD_API_URL=https://127.0.0.1:9000
CLOUD_API_VERIFY_SSL=false

# 目标机如已有 Python，可显式指定
# ZXK_PYTHON_EXE=D:\runtime\python.exe
# ZXK_ALGO_PYTHON_EXE=D:\runtime\python.exe
```

后端读取配置时，建议优先级为：

1. 系统环境变量。
2. 发布包根目录 `config.local.env`。
3. `backend/.env`。
4. 代码默认值。

### 4. 处理前端

如果是纯静态前端：

- 直接复制 `frontend/`。
- 后端通过 `StaticFiles` 挂载该目录。
- 登录页、首页路径使用 URL 编码或英文路径，避免中文路径在不同编码环境下出错。

如果是 Vue/React/Vite：

```bash
cd frontend
npm install
npm run build
```

然后复制 `dist/` 到发布包，例如：

```text
frontend/dist/
```

### 5. 处理后端

后端入口建议统一为：

```bash
cd backend
python run.py
```

`run.py` 应完成：

- 初始化数据库。
- 清理被占用端口。
- 启动算法子服务。
- 启动 FastAPI 主服务。
- 打开浏览器或桌面窗口。
- 退出时清理子进程。

后端路径建议全部从文件位置推导：

```python
from pathlib import Path

BACKEND_DIR = Path(__file__).resolve().parent
APP_ROOT = BACKEND_DIR.parent
FRONTEND_DIR = APP_ROOT / "frontend"
DATA_DIR = BACKEND_DIR / "data"
OUTPUT_DIR = BACKEND_DIR / "output"
```

### 6. 处理 Python 环境

有三种策略。

#### 策略 A：随包放完整虚拟环境

优点：

- 解压后基本可直接运行。
- 对目标机要求最低。

缺点：

- 包很大。
- Python 路径、二进制依赖可能与目标机不兼容。
- 更新依赖成本高。

#### 策略 B：首次启动自动创建虚拟环境

优点：

- 发布包更干净。
- 不把 `python_env` 放进压缩包。
- 目标机首次启动后自动生成 `.runtime/venv`。

缺点：

- 首次启动需要联网，除非准备离线 wheel 包。

推荐启动器流程：

```text
双击 start.bat
  -> 检查 SUMO/DTALite 等随包软件
  -> 查找系统 Python
  -> 没有 Python 时下载并安装用户级 Python
  -> 创建 .runtime/venv
  -> pip install -r backend/requirements.txt
  -> 启动 backend/run.py
  -> 打开 http://localhost:8000
```

#### 策略 C：离线 wheelhouse

适合内网或无互联网机器。

构建机提前下载依赖：

```bash
python -m pip download -r backend/requirements.txt -d installer/wheelhouse
```

目标机安装：

```bash
python -m pip install --no-index --find-links installer/wheelhouse -r backend/requirements.txt
```

## 五、外部软件处理

### SUMO

如果许可证和体积允许，建议随包放入：

```text
tools/sumo/
```

启动时设置：

```bat
set "SUMO_HOME=%APP_ROOT%tools\sumo"
set "PATH=%SUMO_HOME%\bin;%PATH%"
set "PYTHONPATH=%SUMO_HOME%\tools;%PYTHONPATH%"
```

代码中优先使用：

```python
sumo_home = os.environ.get("SUMO_HOME")
```

### DTALite/NEXTA

建议放到算法目录下：

```text
backend/algorithms/traffic_reconstruction/dtalite/
```

调用时使用相对路径：

```python
DTALITE_DIR = APP_ROOT / "backend" / "algorithms" / "traffic_reconstruction" / "dtalite"
```

### CARLA

CARLA 体积通常很大，不建议默认塞进普通发布包。可采用：

- 用户自行安装。
- 独立扩展包。
- 启动时检测 `CARLA_ROOT`。
- 文档给出下载和路径配置方式。

## 六、生成便携压缩包

PowerShell 示例：

```powershell
$Version = "v3.4.4"
$Root = "D:\project"
$ReleaseRoot = "$Root\output_demo"
$Package = "$ReleaseRoot\平台名称_本地_$Version"

New-Item -ItemType Directory -Force $Package | Out-Null

Copy-Item "$Root\backend" "$Package\backend" -Recurse -Force
Copy-Item "$Root\frontend" "$Package\frontend" -Recurse -Force
Copy-Item "$Root\license" "$Package\license" -Recurse -Force
Copy-Item "$Root\installer" "$Package\installer" -Recurse -Force
Copy-Item "$Root\tools\sumo" "$Package\tools\sumo" -Recurse -Force
Copy-Item "$Root\README.md" "$Package\README.md" -Force
Copy-Item "$Root\config.local.env" "$Package\config.local.env" -Force
Copy-Item "$Root\启动平台.bat" "$Package\启动平台.bat" -Force

# 清理不应发布的内容
Get-ChildItem $Package -Recurse -Force -Directory -Filter "__pycache__" | Remove-Item -Recurse -Force
Get-ChildItem $Package -Recurse -Force -Directory -Filter ".pytest_cache" | Remove-Item -Recurse -Force
Remove-Item "$Package\backend\logs" -Recurse -Force -ErrorAction SilentlyContinue
Remove-Item "$Package\backend\uploads" -Recurse -Force -ErrorAction SilentlyContinue
Remove-Item "$Package\.runtime" -Recurse -Force -ErrorAction SilentlyContinue

Compress-Archive -Path $Package -DestinationPath "$ReleaseRoot\平台名称_本地_$Version.zip" -Force
```

## 七、生成安装包

当便携包稳定后，可以制作安装器。

推荐工具：

- Inno Setup：Windows 安装包，简单稳定。
- NSIS：脚本能力强。
- WiX Toolset：适合企业级 MSI。

Inno Setup 思路：

```ini
[Setup]
AppName=平台名称
AppVersion=3.4.4
DefaultDirName={localappdata}\平台名称
DefaultGroupName=平台名称
OutputBaseFilename=平台名称_本地_v3.4.4_Setup
Compression=lzma
SolidCompression=yes

[Files]
Source: "output_demo\平台名称_本地_v3.4.4\*"; DestDir: "{app}"; Flags: recursesubdirs ignoreversion

[Icons]
Name: "{group}\启动平台"; Filename: "{app}\启动平台.bat"
Name: "{commondesktop}\启动平台"; Filename: "{app}\启动平台.bat"

[Run]
Filename: "{app}\启动平台.bat"; Description: "启动平台"; Flags: postinstall nowait skipifsilent
```

## 八、发布检查清单

发布前至少检查：

- 目标目录不存在 `python_env` 或 `.runtime`，除非这是有意的离线整包。
- 没有开发机绝对路径，例如 `D:\开发目录\...`。
- 没有密钥、Token、私有 API Key。
- `backend/run.py` 存在。
- `frontend/index.html` 或登录页存在。
- `tools/sumo/bin/sumo-gui.exe` 存在。
- DTALite/NEXTA 等外部程序存在。
- `requirements.txt` 存在。
- `启动平台.bat` 存在。
- 解压到非开发目录后能启动，例如桌面、`D:\test_release\`、中文路径目录。
- 端口冲突时有提示或自动处理。
- 首次启动和第二次启动都测试通过。

常用扫描命令：

```powershell
rg -n "D:\\开发目录|sk-[A-Za-z0-9]{20,}|python_env" release\平台名称_本地_vX.Y.Z
Get-ChildItem release\平台名称_本地_vX.Y.Z -Recurse -Force -Directory -Filter python_env
Get-ChildItem release\平台名称_本地_vX.Y.Z -Recurse -Force -Directory -Filter __pycache__
```

## 九、发布到另一台电脑

### 便携包发布

流程：

1. 将 `平台名称_本地_vX.Y.Z.zip` 拷贝到目标电脑。
2. 解压到目标目录，例如 `D:\平台名称\`。
3. 双击 `启动平台.bat`。
4. 首次启动自动创建运行环境或提示缺少环境。
5. 浏览器打开本地页面。

### 安装包发布

流程：

1. 运行 `平台名称_本地_vX.Y.Z_Setup.exe`。
2. 安装到用户目录或指定目录。
3. 从桌面快捷方式启动。
4. 首次启动自动完成运行时配置。

### 服务器/云平台发布

如果发布到服务器，应采用另一套方案：

- 前端：Nginx 托管静态文件。
- 后端：Uvicorn/Gunicorn 或 Windows Service/Linux systemd。
- 数据库：SQLite 可用于单机，正式多用户建议 PostgreSQL/MySQL。
- 算法服务：独立进程、容器或任务队列。
- 外部软件：SUMO/DTALite 安装到固定服务目录，并通过环境变量配置。
- 部署：Docker Compose、CI/CD、版本镜像。

## 十、版本与交付物命名

建议命名：

```text
平台名称_本地_v3.4.4.zip
平台名称_本地_v3.4.4_Setup.exe
平台名称_本地_v3.4.4_SHA256.txt
平台名称_本地_v3.4.4_发布说明.md
```

发布说明应包含：

- 版本号。
- 发布时间。
- 新增功能。
- 修复内容。
- 已知问题。
- 安装/启动方式。
- 环境要求。
- 校验哈希。

## 十一、推荐落地方案

对于本地教学/演示类平台，推荐采用：

```text
便携包 + 首次启动 bootstrap + 包内 SUMO + 包内 DTALite + 本地 SQLite
```

具体策略：

- 不随包放开发机的 `python_env`。
- 首次启动时自动创建 `.runtime/venv`。
- 依赖通过 `requirements.txt` 安装。
- 无网环境额外提供 `installer/wheelhouse` 离线依赖包。
- 前端作为静态资源由 FastAPI 挂载。
- 所有算法输出写入包内运行时目录或后端 output 目录。
- 外部软件路径优先使用包内相对路径。

这样可以兼顾包体积、可迁移性和后续维护成本。
