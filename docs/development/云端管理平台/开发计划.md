# 云端管理平台 — 开发计划

> 文档版本：v1.1 | 编写日期：2026-02-21
> 
> 说明：云端管理平台是独立项目，后端语言不限（Go/Node.js/Python/Java等均可）。
> 本文档描述的是通用的开发任务和架构模式，不绑定特定技术栈。

## 一、开发阶段划分

云端管理平台的开发分为三个迭代，每个迭代交付可用的功能：

```
迭代1（1.5周）          迭代2（1周）           迭代3（0.5周）
基础框架 + License     任务同步 + 报告收集     统计分析 + 更新推送
    │                      │                      │
    ▼                      ▼                      ▼
┌──────────┐         ┌──────────┐          ┌──────────┐
│ 项目搭建  │         │ 任务CRUD  │          │ 数据采集  │
│ 数据库    │         │ 云端↔本地  │          │ 统计报表  │
│ 用户认证  │         │ 同步接口  │          │ 版本更新  │
│ License  │         │ 报告上传  │          │ 管理后台  │
│ 激活验证  │         │ 在线评阅  │          │ 页面完善  │
│ 管理后台  │         │          │          │          │
│ 基础页面  │         │          │          │          │
└──────────┘         └──────────┘          └──────────┘
```

## 二、迭代1：基础框架 + License（预计1.5周）

### 任务清单

| # | 任务 | 预估工时 | 优先级 |

| 5 | 用户注册/登录API（JWT认证） | 4h | P0 |
| 6 | License生成API（管理员） | 4h | P0 |
| 7 | License激活API（客户端调用） | 6h | P0 |
| 8 | License验证API | 2h | P0 |
| 9 | 本地客户端集成：启动时License检查 | 6h | P0 |
| 10 | 管理后台前端：登录页 + 概览页 | 6h | P1 |
| 11 | 管理后台前端：机构管理页 + License管理页 | 8h | P1 |
| 12 | Docker Compose部署配置 + Dockerfile | 4h | P1 |

**迭代1交付物：**
- 云端服务可部署运行

## 五、项目目录结构

云端管理平台是一个独立项目，目录结构取决于所选语言，但逻辑分层一致。

以下是通用的逻辑结构（具体文件名/后缀因语言而异）：

```
cloud/                              # 云端管理平台（独立项目）
├── cmd/ 或 app/                    # 应用入口
│   └── main.*                      # 启动文件
├── config/                         # 配置管理
│   └── config.*                    # 数据库URL、密钥、端口等
├── internal/ 或 src/               # 核心业务代码
│   ├── models/                     # 数据模型 / Entity
│   │   ├── organization.*
│   │   ├── license.*
│   │   ├── user.*
│   │   ├── task.*
│   │   ├── report.*
│   │   └── analytics.*
│   ├── handlers/ 或 controllers/   # 路由处理 / Controller
│   │   ├── auth.*
│   │   ├── license.*
│   │   ├── tasks.*
│   │   ├── reports.*
│   │   ├── sync.*
│   │   ├── analytics.*
│   │   └── admin.*
│   ├── services/                   # 业务逻辑
│   │   ├── auth.*
│   │   ├── license.*
│   │   ├── sync.*
│   │   └── analytics.*
│   ├── repository/ 或 dao/         # 数据访问层
│   │   ├── user_repo.*
│   │   ├── task_repo.*
│   │   └── ...
│   └── middleware/                  # 中间件（认证、日志、CORS等）
│       ├── auth.*
│       └── logging.*
├── migrations/                     # 数据库迁移脚本（SQL）
│   ├── 001_init.sql
│   └── ...
├── frontend-admin/                 # 管理后台前端（纯静态，Nginx托管）
│   ├── index.html
│   ├── login.html
│   ├── pages/
│   │   ├── dashboard.html
│   │   ├── organizations.html
│   │   ├── licenses.html
│   │   ├── users.html
│   │   ├── tasks.html
│   │   ├── reports.html
│   │   └── analytics.html
│   └── assets/
│       ├── css/
│       └── js/
├── deploy/                         # 部署配置
│   ├── docker-compose.yml
│   ├── Dockerfile
│   ├── nginx.conf
│   └── init.sql
├── tests/                          # 测试
│   ├── auth_test.*
│   ├── license_test.*
│   └── sync_test.*
├── Makefile 或 justfile             # 构建/运行/测试命令
└── README.md
```

> 说明：`*` 表示文件后缀取决于语言选择（`.go` / `.py` / `.ts` / `.java` 等）。
> 逻辑分层（Handler → Service → Repository → Model）是通用模式，不随语言变化。

## 六、与本地客户端的集成改动

云端管理平台开发的同时，本地客户端需要做以下改动：

| 改动 | 涉及文件 | 说明 |
|------|---------|------|
| License检查 | `desktop_app.py` | 启动时验证激活状态 |
| 任务同步 | `backend/app/services/sync.py`（新增） | 定时从云端拉取任务 |
| 报告上传 | `backend/app/services/report.py` | 提交报告时同时上传云端 |
| 数据上报 | `backend/app/services/analytics.py`（新增） | 定时上报使用数据 |
| 更新检查 | `desktop_app.py` | 启动时检查新版本 |
| 云端配置 | `backend/app/config.py` | 新增云端API地址配置 |
