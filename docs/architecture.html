云端管理平台 — 平台定位与架构设计

文档版本：v1.1 | 编写日期：2026-02-21

说明：云端管理平台与本地客户端通过 HTTP API + JSON 通信，两边实现语言完全解耦。 本文档描述的是通用架构模式和接口契约，不绑定特定编程语言。

一、平台定位

1.1 为什么需要云端管理平台？

本地离线客户端解决了"实验功能运行"的问题，但以下场景无法仅靠本地客户端实现：

场景 问题 云端平台的作用
多教室部署 教师在A教室发的任务，B教室的学生看不到 统一任务下发，所有客户端同步
软件授权 安装包可以无限复制，无法控制分发 License发放与机器码绑定
报告收集 学生报告散落在各台电脑上，教师无法统一查看 报告统一上传到云端，教师在线批阅
使用统计 不知道哪些学校在用、用了多少 使用数据汇总，生成报表
版本更新 需要逐台电脑手动更新 推送更新通知，客户端自动下载

1.2 核心原则

  • 轻量级：不运行任何算法或仿真，仅做数据管理和同步
  • 低成本：2核4G云服务器即可支撑数百用户
  • 非必需：断网后本地客户端所有实验功能正常使用，云端仅在联网时同步

三、云端平台技术架构

3.1 技术选型原则

云端管理平台是一个独立的Web服务，不依赖本地客户端的Python技术栈。选型遵循以下原则：

  • 语言无关：后端可以用任何成熟的Web框架（Go/Gin、Java/Spring Boot、Node.js/Express、Python/FastAPI、Rust/Axum等），根据团队熟悉度和性能需求选择
  • 标准协议：对外只暴露RESTful JSON API，本地客户端通过HTTP调用，不关心云端用什么语言实现
  • 通用架构模式：采用经典的三层架构（Controller → Service → Repository），任何语言都适用
组件 要求 候选方案
后端API RESTful JSON，支持JWT认证 Go/Gin, Java/Spring Boot, Node.js/Express, Python/FastAPI, Rust/Axum 等
数据库 关系型，支持并发 PostgreSQL（推荐）、MySQL
反向代理 HTTPS终止，静态文件托管 Nginx, Caddy
文件存储 报告文件、更新包 本地磁盘（初期），对象存储（后续）
部署方式 容器化，一键部署 Docker Compose
管理后台前端 SPA或SSR均可 React, Vue, 纯HTML/JS, 或后端模板渲染

关键点：云端平台和本地客户端之间的契约是 HTTP API + JSON，两边的实现语言完全解耦。

3.3 数据库设计

-- 学校/机构表
CREATE TABLE organizations (
    id SERIAL PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    contact_name VARCHAR(50),
    contact_phone VARCHAR(20),
    license_count INT DEFAULT 0,
    created_at TIMESTAMP DEFAULT NOW()
);

-- License表
CREATE TABLE licenses (
    id SERIAL PRIMARY KEY,
    license_key VARCHAR(64) UNIQUE NOT NULL,
    org_id INT REFERENCES organizations(id),
    machine_id VARCHAR(128),          -- 绑定的机器码
    license_type VARCHAR(20) NOT NULL, -- trial/education/permanent
    activated_at TIMESTAMP,
    expires_at TIMESTAMP,
    is_active BOOLEAN DEFAULT TRUE,
    created_at TIMESTAMP DEFAULT NOW()
);

-- 云端用户表（与本地用户同步）
CREATE TABLE cloud_users (
    id SERIAL PRIMARY KEY,
    username VARCHAR(50) NOT NULL,
    password_hash VARCHAR(255) NOT NULL,
    role VARCHAR(20) NOT NULL,
    real_name VARCHAR(50),
    org_id INT REFERENCES organizations(id),
    local_user_id INT,                -- 对应本地客户端的user id
    last_sync_at TIMESTAMP,
    created_at TIMESTAMP DEFAULT NOW(),
    UNIQUE(username, org_id)
);

-- 云端任务表
CREATE TABLE cloud_tasks (
    id SERIAL PRIMARY KEY,
    title VARCHAR(200) NOT NULL,
    description TEXT,
    module_id VARCHAR(50),
    teacher_id INT REFERENCES cloud_users(id),
    org_id INT REFERENCES organizations(id),
    deadline TIMESTAMP,
    status VARCHAR(20) DEFAULT 'draft',
    created_at TIMESTAMP DEFAULT NOW()
);

-- 云端报告表
CREATE TABLE cloud_reports (
    id SERIAL PRIMARY KEY,
    task_id INT REFERENCES cloud_tasks(id),
    student_id INT REFERENCES cloud_users(id),
    file_path VARCHAR(500),
    file_name VARCHAR(255),
    score REAL,
    feedback TEXT,
    status VARCHAR(20) DEFAULT 'submitted',
    is_late BOOLEAN DEFAULT FALSE,
    submitted_at TIMESTAMP DEFAULT NOW(),
    graded_at TIMESTAMP
);

-- 使用统计表
CREATE TABLE analytics (
    id SERIAL PRIMARY KEY,
    license_id INT REFERENCES licenses(id),
    org_id INT REFERENCES organizations(id),
    report_date DATE NOT NULL,
    active_users INT DEFAULT 0,
    experiment_count INT DEFAULT 0,
    module_usage JSONB,               -- {"signal_opt": 15, "path_guidance": 8, ...}
    created_at TIMESTAMP DEFAULT NOW()
);

-- 同步日志表
CREATE TABLE sync_logs (
    id SERIAL PRIMARY KEY,
    license_id INT REFERENCES licenses(id),
    sync_type VARCHAR(50),            -- users/tasks/reports/analytics
    direction VARCHAR(10),            -- upload/download
    record_count INT DEFAULT 0,
    status VARCHAR(20),
    synced_at TIMESTAMP DEFAULT NOW()
);

四、API接口设计

4.1 接口总览

所有云端API以 /api/cloud/ 为前缀，与本地客户端的 /api/v1/ 区分。

认证相关：
  POST   /api/cloud/auth/register        用户注册
  POST   /api/cloud/auth/login           登录获取token
  POST   /api/cloud/auth/refresh         刷新token

License相关：
  POST   /api/cloud/license/activate     激活License
  GET    /api/cloud/license/verify       验证License状态
  POST   /api/cloud/license/generate     生成License（管理员）

数据同步：
  POST   /api/cloud/sync/users           同步用户数据
  GET    /api/cloud/sync/tasks           拉取任务更新
  POST   /api/cloud/sync/reports         上传报告
  POST   /api/cloud/sync/analytics       上报使用数据

任务管理：
  GET    /api/cloud/tasks                获取任务列表
  POST   /api/cloud/tasks                创建任务
  PUT    /api/cloud/tasks/:id            更新任务
  DELETE /api/cloud/tasks/:id            删除任务

报告管理：
  GET    /api/cloud/reports              获取报告列表
  GET    /api/cloud/reports/:id/download 下载报告文件
  PUT    /api/cloud/reports/:id/grade    评分

用户管理：
  GET    /api/cloud/users                获取用户列表
  POST   /api/cloud/users/import         批量导入用户
  PUT    /api/cloud/users/:id            更新用户信息

统计分析：
  GET    /api/cloud/analytics/overview   总览数据
  GET    /api/cloud/analytics/usage      使用趋势
  GET    /api/cloud/analytics/modules    模块使用统计

版本更新：
  GET    /api/cloud/updates/check        检查更新
  GET    /api/cloud/updates/download     下载更新包

管理后台：
  GET    /api/cloud/admin/organizations  机构列表
  POST   /api/cloud/admin/organizations  创建机构
  GET    /api/cloud/admin/dashboard      仪表盘数据

五、部署方案

5.1 Docker Compose 部署

无论后端用什么语言，部署结构都是一样的：三个容器（反向代理 + API服务 + 数据库）。

# docker-compose.cloud.yml
version: '3.8'

services:
  nginx:
    image: nginx:alpine
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./nginx.conf:/etc/nginx/nginx.conf
      - ./ssl:/etc/nginx/ssl
      - ./frontend-admin:/usr/share/nginx/html
    depends_on:
      - api

  api:
    build: ./cloud-api          # Dockerfile根据所选语言编写
    environment:
      - DATABASE_URL=postgresql://user:pass@db:5432/zhixinyoukong
      - SECRET_KEY=${SECRET_KEY}
      - PORT=8080
    volumes:
      - ./data/uploads:/app/uploads
    depends_on:
      - db

  db:
    image: postgres:15-alpine
    environment:
      - POSTGRES_DB=zhixinyoukong
      - POSTGRES_USER=user
      - POSTGRES_PASSWORD=pass
    volumes:
      - pgdata:/var/lib/postgresql/data

volumes:
  pgdata:

Dockerfile 示例因语言而异：Go项目可以用多阶段构建产出一个极小的二进制镜像；Node.js项目用 node:alpine；Python项目用 python:3.11-slim。但 docker-compose 的编排结构不变。

5.2 服务器配置建议

规模 服务器配置 预估成本（月）
小型（1-3所学校，<200用户） 2核4G，50G SSD ~100元
中型（5-10所学校，<1000用户） 4核8G，100G SSD ~300元
大型（10+所学校，1000+用户） 8核16G，200G SSD ~800元

由于云端不运行任何算法，主要开销是数据库查询和文件存储，配置需求极低。
