HIL 虚实结合仿真平台介绍

1. 平台入口

平台访问地址：

http://10.8.129.232:5173/

该地址对应的是一个独立的 HIL 虚实结合仿真前端，页面标题为“HIL 虚实结合仿真平台”。从前端源码和接口信息看，该平台采用 Vue 3 + Vite 构建，前端项目名称为 hil-platform-frontend，主要用于真实小车、虚拟小车、校园地图、点云地图、道路拓扑和车端指令的统一管理。

2. 平台定位

该平台面向硬件在环（Hardware-in-the-Loop, HIL）和虚实结合仿真实验，核心目标是把真实智能小车、虚拟小车、校园地图、点云环境和 MQTT/ROS 通信链路整合到同一套可视化界面中。

它不是普通的静态展示页面，而是一个支持实时数据接入、车辆状态监控、路径指令下发和道路拓扑交互的运行平台。平台可以用于：

  • 查看真实车和虚拟车的在线状态；
  • 在校园地图上展示车辆位置、轨迹和路径；
  • 叠加 LiDAR 点云环境，实现真实地图和车辆位姿对齐；
  • 通过 MQTT/ROS 话题接收真实车里程计、点云、道路拓扑等信息；
  • 向车辆下发路径切换、自主运行、状态检查、停止等控制指令；
  • 观察真实车与虚拟车在同一地图坐标体系下的运行情况。

3. 技术组成

根据页面源码和接口返回信息，平台主要技术组成如下：

层次 技术或模块 作用
前端框架 Vue 3、Vite、TypeScript 构建单页应用和交互界面
状态与组件 Pinia、Element Plus 页面状态管理与 UI 组件
可视化 ECharts、SVG 地图、点云栅格图层 展示运行态势、校园地图和点云叠加
实时通信 SockJS、STOMP WebSocket 订阅车辆、指令和道路拓扑实时事件
车端通信 MQTT、ROS topic 接收真实车里程计、点云、路径和拓扑信息
后端接口 /api/* 提供登录、车辆、地图、路线、指令和拓扑状态接口

前端会连接 WebSocket 地址 /ws，并订阅以下实时通道：

  • /topic/cars
  • /topic/commands
  • /topic/road-topology

4. 页面结构

平台左侧导航包含四个主要页面：

页面 主要作用
总览地图 展示大连理工大学主校区高精度俯视地图、车辆位置、路线、地图图层和运行态势
经管学院 展示经管学院 HIL 实验区域，重点用于 LiDAR 点云、导航路点和车辆位姿贴合
小车管理 管理真实车和虚拟车，包括车辆编号、类型、在线状态、通信链路、遥测信息等
指令记录 查看平台向车辆下发的控制指令及其发送、回执和执行状态

页面顶部显示当前地图与系统状态，侧边栏显示服务器在线状态、当前用户和系统时间。平台支持白天/黑夜两种主题模式。

5. 核心功能

5.1 登录与权限

平台提供登录功能，默认登录表单中可见 admin / admin123。接口返回的用户角色包括：

  • SUPER_ADMIN
  • OPERATOR
  • VIEWER

其中具备 SUPER_ADMIN 或 OPERATOR 角色的用户可以执行车辆操作和指令下发。

5.2 车辆实时监控

平台当前接口返回的车辆摘要为：

指标 当前值
接入车辆数 2

虚拟车数量 1

当前接入车辆包括：

车辆状态字段包括：

5.4 LiDAR 点云与位姿贴合

“经管学院”页面侧重 HIL 实验区域的点云叠加与位姿贴合。平台支持：

  • LiDAR 点云图层显示；
  • 点云与校园地图坐标对齐；
  • 车辆在点云图层上的实时位置投影；
  • YAML 导航路点展示；
  • SEM 闭环道路、道路匹配闭环、原地等待等路线模式；
  • 路线替换或追加到队列。

页面中可选的点云路线包括：

  • NAVIGATION_WAYPOINTS_LATEST
  • SEM_10M_BUILDING_LOOP
  • SEM_ROAD_MATCHED_LOOP
  • HOLD_POSITION

路线下发模式包括：

  • 替换当前路线；
  • 追加到队列。

5.6 指令下发与记录

平台支持向车辆下发多种控制指令，包括：

  • CHANGE_ROUTE：切换或下发路线；
  • ENABLE_AUTONOMY：启用自主运行；
  • SYNC_ROUTE：同步路线；
  • STATUS_CHECK：检查车辆状态；
  • STOP：停止车辆。

所有指令会进入指令记录页面，记录内容包括：

  • 指令 ID；
  • 目标车辆；
  • 指令类型；
  • 参数载荷；
  • 指令状态；
  • 操作人；
  • 请求时间；
  • 发送时间；
  • 回执时间；
  • 错误信息。

6. 与综合交通实验平台的关系

在当前综合交通实验平台中，http://10.8.129.232:5173/ 更接近一个“原生 HIL 车辆与地图运行平台”。它与主平台中的“车规级智能车辆开发与控制”“虚实结合仿真场景构建”等功能存在对应关系。

主平台负责交通算法、教学实验、SUMO/CARLA 联合仿真等综合功能；该 HIL 页面则更聚焦真实小车、点云地图、MQTT/ROS 数据链路和车端控制。二者结合后，可以形成如下链路：

  1. 主平台进行交通算法配置和仿真验证；
  2. HIL 平台接入真实车或虚拟车状态；
  3. 车辆位置、速度、航向、路径和拓扑信息通过 MQTT/ROS 回传；
  4. 平台在统一地图和点云环境中展示真实车与虚拟车；
  5. 操作端下发路径、目标节点或控制指令；
  6. 车端执行后再将状态回传，形成虚实闭环。

7. 平台价值

该平台的价值主要体现在三个方面：

第一，支撑真实车与虚拟车统一管理。
平台同时展示 REAL-001 和 VIR-001，能够在同一坐标体系下观察真实车辆和虚拟车辆的运行状态。

第二，支撑 HIL 闭环验证。
通过 MQTT/ROS 话题接收真实车状态，并支持目标节点和路线指令下发，使平台具备硬件在环闭环测试能力。

第三，支撑高精度场景对齐。
平台结合校园地图、SUMO 路网、LiDAR 点云和导航路点，使车辆位置能够在地图和点云环境中统一展示，为虚实融合实验提供坐标基础。

8. 简要汇报表述

可以向老师或项目负责人这样介绍：

http://10.8.129.232:5173/ 是 HIL 虚实结合仿真平台的原生前端界面，主要用于真实小车和虚拟小车的统一管理、校园地图与点云地图展示、MQTT/ROS 实时通信接入、道路拓扑状态展示以及车端控制指令下发。当前平台已接入 1 台真实小车和 1 台虚拟小车，支持在同一地图坐标体系下查看车辆位置、速度、航向、电量和通信状态，并可向车辆下发路线切换、自主运行、状态检查、停止和目标节点等指令。该页面与综合交通实验平台中的虚实融合和车规级智能车辆控制功能相对应，是实现真实车、虚拟场景和控制指令闭环交互的重要组成部分。
