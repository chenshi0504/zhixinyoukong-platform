# 云端管理平台 — 功能规格说明

> 文档版本：v1.0 | 编写日期：2026-02-21

## 一、License授权管理

### 1.1 功能描述

控制软件的分发和使用，防止安装包被无限复制。

### 1.2 激活流程

```
┌──────────┐     ┌──────────┐     ┌──────────┐
│ 用户安装  │     │ 首次启动  │     │ 输入激活码│
│ 软件      │────►│ 生成机器码│────►│          │
└──────────┘     └──────────┘     └─────┬────┘
                                        │
                                        ▼
                                  ┌──────────┐
                                  │ 发送到云端│
                                  │ 验证     │
                                  └─────┬────┘
                                        │
                              ┌─────────┴─────────┐
                              │                   │
                              ▼                   ▼
                        ┌──────────┐        ┌──────────┐
                        │ 验证通过  │        │ 验证失败  │
                        │ 绑定机器码│        │ 提示错误  │
                        │ 返回令牌  │        │          │
                        └─────┬────┘        └──────────┘
                              │
                              ▼
                        ┌──────────┐
                        │ 本地保存  │
                        │ 激活令牌  │
                        │ 正常使用  │
                        └──────────┘
```

### 1.3 License类型

| 类型 | 有效期 | 绑定方式 | 适用场景 |
|------|--------|---------|---------|
| 试用版 | 30天 | 绑定机器码 | 客户评估 |
| 教育版 | 按学期（6个月） | 绑定机构+机器码 | 高校教学 |
| 永久版 | 无限期 | 绑定机器码 | 长期合作客户 |

### 1.4 机器码生成规则

```
// 取CPU序列号 + 硬盘序列号 + 主板序列号
// SHA256哈希 → 32位机器码
machine_id = SHA256(cpu_id + disk_id + board_id)[:32]
```

> 本地客户端用Python实现此逻辑（因为客户端是Python），云端只需要存储和比对这个字符串。

## 二、用户与机构管理

### 2.1 机构管理

- 每个客户（学校/企业）作为一个"机构"
- 机构下可以有多个License（对应多台电脑）
- 机构下的用户数据互相隔离

### 2.2 用户角色

| 角色 | 云端权限 | 说明 |
|------|---------|------|
| 超级管理员 | 全部 | 我方运营人员 |
| 机构管理员 | 本机构数据 | 学校IT管理员 |
| 教师 | 本机构任务/报告 | 授课教师 |
| 学生 | 自己的数据 | 通过本地客户端同步 |

---

## 三、任务同步

### 3.1 同步规则

- 教师在云端管理后台或本地客户端创建任务
- 任务发布后，所有属于该机构的本地客户端在下次同步时获取
- 同步间隔：客户端启动时 + 每5分钟自动检查

### 3.2 任务数据结构

```json
{
  "id": 1,
  "title": "实验一：交通信号优化",
  "description": "使用TuRBO算法优化交叉口信号配时...",
  "module_id": "signal_optimization",
  "deadline": "2026-03-15T23:59:59",
  "status": "published",
  "teacher_name": "张老师",
  "org_id": 1,
  "created_at": "2026-02-21T10:00:00",
  "updated_at": "2026-02-21T10:00:00"
}
```

## 四、报告收集与评阅

### 4.1 报告上传流程

1. 学生在本地客户端提交报告（PDF/DOCX）
2. 报告先保存到本地 `uploads/` 目录
3. 联网时自动上传到云端
4. 云端存储文件并创建报告记录
5. 教师在云端管理后台或本地客户端查看并评阅

### 4.2 评阅功能

- 在线预览报告（PDF直接预览，DOCX转换后预览）
- 打分（0-100分）
- 文字反馈
- 评阅结果同步回本地客户端

## 五、使用数据统计

### 5.1 采集的数据

| 数据项 | 说明 | 采集频率 |
|--------|------|---------|
| 活跃用户数 | 当日登录的用户数 | 每30分钟 |
| 实验运行次数 | 各模块的运行次数 | 每30分钟 |
| 模块使用分布 | 哪些模块用得多 | 每30分钟 |
| 算法使用统计 | 各算法的使用次数 | 每30分钟 |
| 学生代码提交数 | 自定义算法的提交次数 | 每30分钟 |

### 5.2 统计报表

管理后台提供以下报表：
- 各机构使用概览（活跃度排名）
- 模块使用热力图（哪些功能最受欢迎）
- 时间趋势图（使用量随时间变化）
- 导出为Excel/CSV

## 六、版本更新推送

### 6.1 更新流程

```
我方发布新版本
    │
    ▼
上传更新包到云端
    │
    ▼
本地客户端启动时检查更新
    │
    ├── 有新版本 → 弹窗提示用户
    │                │
    │                ├── 用户选择"立即更新" → 下载并安装
    │                └── 用户选择"稍后提醒" → 下次启动再提示
    │
    └── 无新版本 → 正常启动
```

### 6.2 更新信息结构

```json
{
  "latest_version": "1.2.0",
  "release_date": "2026-03-01",
  "release_notes": "1. 新增XX功能\n2. 修复XX问题",
  "download_url": "/api/cloud/updates/download?version=1.2.0",
  "file_size": "150MB",
  "is_mandatory": false
}
```
